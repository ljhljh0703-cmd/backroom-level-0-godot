## Enhancement Direction

### 1. Make The Flow Data-Driven

Goal: changing the route should require editing data, not hunting through gameplay code.

Recommended changes:

- Extract room definitions from `src/Game.gd` into a `rooms.json` or Godot `Resource`.
- Add fields for `id`, `image`, `foreground`, `caption`, `hotspots`, `tags`, and `entry_events`.
- Add a validation script for missing targets, missing images, duplicate ids, and unreachable rooms.

Payoff: faster iteration and fewer accidental broken paths.

### 2. Add A Review Overlay

Goal: make feedback about click areas precise.

Recommended changes:

- Add a dev toggle that draws hotspot rectangles and labels.
- Show current `room_id`, `move_count`, `creature_stage`, and event flags in a corner.
- Keep this hidden in release builds or behind a debug flag.

Payoff: user can say "left hotspot too wide" or "door click should start here" without guessing.

### 3. Separate Creature Timeline From Room Logic

Goal: adjust creature timing without rewriting navigation.

Recommended changes:

- Create a `creature_beats` table:
  - trigger condition
  - room id
  - delay
  - duration
  - screen position
  - alpha/scale
  - sound/shake
- Keep the current STOP peek as beat 1.
- Add later beats only after flow approval.

Payoff: creature pacing becomes tunable and reviewable.

### 4. Build The Two-Minute Route As Beats

Goal: control pacing for a very short game.

Suggested beat structure:

| Beat | Target Duration | Purpose |
| --- | ---: | --- |
| Entry fork | 10-20s | Establish STOP, left/right choice, red trace. |
| First path | 15-25s | Let player inspect clue with no creature. |
| Return reveal | 5-8s | First creature peek behind STOP sign. |
| Deeper route | 30-45s | Route opens toward hallway/junction/sign. |
| Exit bait | 20-30s | EXIT sign and final door. |
| Ending | 10-15s | Jump/false exit/loop. |

Payoff: scope remains under 2 minutes.

### 5. Do Final Art As A Single Pass

Goal: preserve consistency.

Recommended process:

- Approve all room layouts first using blockout.
- Create a shot list from `ROOM_DATA`.
- Generate or import final background images for every room in the same style pass.
- Keep filenames stable: `bg_start.png`, `bg_left_path.png`, etc.
- Only after all backgrounds are ready, tune captions, audio, and creature placement to the final images.

Payoff: no more per-room visual drift.

### 6. Add Lightweight QA Before Each Deploy

Goal: prevent broken Pages builds and broken routes.

Checklist:

- `python3 tools/generate_assets.py`
- `godot --headless --path . --import`
- `godot --headless --path . --export-release Web builds/web/index.html`
- open local web build
- verify first room, left path, right path, return reveal
- deploy `builds/web` to `gh-pages`
- verify deployed `index.pck` hash matches local export
