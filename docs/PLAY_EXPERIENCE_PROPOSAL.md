# Play Experience Proposal: v3 Direction

상태: v2 블록아웃 이후 제안

## 목표

현재 v2는 구조 검증용이다. 다음 고도화는 "정답을 숨기되, 나중에 보면 공정했다"는 감각을 만드는 쪽이 좋다.

## 추천 플레이 흐름

| Beat | 플레이어 행동 | 감정 목표 | 구현 방향 |
| --- | --- | --- | --- |
| 1. 첫 갈림길 | STOP, 왼쪽 핏자국, 오른쪽 깨끗한 길 확인 | 어디가 더 위험한지 판단하게 함 | STOP 뒤 공간은 클릭 가능하지만 첫 진입은 아무것도 없는 어두운 방 |
| 2. 안전해 보이는 오른쪽 | 판넬을 지나 막다른 길 확인 | 안전한 선택이 헛수고였다는 위화감 | 판넬 클릭 단서, 복귀 시 판넬 소리 |
| 3. 첫 크리처 인지 | 갈림길 복귀 | 짧게 봤지만 확신 못 하는 불안 | STOP 뒤 1초 등장. 현재 `data/rooms.json`의 `right_return_peek`로 조절 |
| 4. 위험해 보이는 왼쪽 | 핏자국과 버튼 확인 | 위험한 길에 정답 단서가 있다는 학습 | 흔적 단서 + 전등 버튼 |
| 5. 붉어진 STOP 뒤 | 버튼 이후 STOP 뒤 공간 재방문 | 초반에 봤던 공간이 바뀐 것을 확인 | 어두운 방에서 붉은 방으로 전환 |
| 6. 출구 판정 | 붉은 방의 빛 클릭 | 단서 수집 여부가 엔딩을 가름 | 단서 충분하면 A, 부족하면 B |

## B 엔딩 고도화 제안

B는 단순 실패보다 "탈출인 줄 알고 뛰어들었는데 다시 백룸"이 좋아 보인다.

추천 연출:

1. 붉은 방에서 빛을 누름.
2. 단서가 부족하면 즉시 문이 열리는 대신 뒤에서 발소리/흔들림.
3. 플레이어가 선택한 게 아니라 몰려 들어간 느낌으로 `false_exit_room` 전환.
4. 캡션은 설명보다 짧게: `나간 줄 알았다.`

이 구조면 나중에 B 전용 추격 컷을 추가해도 현재 route를 갈아엎지 않아도 된다.

## 단서 설계 조정안

현재 A 조건은 `전등 버튼 + 붉은 STOP 뒤 확인 + 붉은 흔적 + 인간형 판넬`이다.

다음 리뷰에서 볼 점:

- 조건이 너무 빡빡하면 `인간형 판넬`은 B 회피 단서가 아니라 추가 해석 단서로 낮춘다.
- 조건이 너무 쉽다면 `붉은 흔적` 클릭 후 버튼 문구를 조금 더 애매하게 만든다.
- 전등 버튼은 반드시 시각 변화로 보상한다. 텍스트만으로 끝내면 조작감이 약하다.

## 다음 구현 후보

1. B 엔딩 진입 직전 2-3초 추격 beat 추가.
2. `creature_beats`를 여러 개로 확장해서 위치/지속시간/사운드를 JSON에서 조절.
3. 단서 클릭 후 작은 상태 변화 추가. 예: 판넬 조사 후 복귀 소리 타이밍 변화.
4. 최종 이미지 전 shot list 작성: 각 방의 카메라 방향, 주요 오브젝트, 클릭 영역 기준.
